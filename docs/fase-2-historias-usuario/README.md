# Fase 2 – Historias de Usuario

Esta carpeta contiene la **Fase 2 del proyecto Paulito Shoes Store**, enfocada en la **definición de historias de usuario** como base funcional del sistema e-commerce.

En esta fase se transforman los requerimientos levantados en la Fase 1 en **necesidades concretas del usuario**, redactadas bajo un enfoque ágil y priorizadas según su importancia para el negocio.

---

## Objetivo de la Fase 2

- Traducir los requerimientos funcionales en historias de usuario claras y entendibles.
- Representar el flujo real de negocio desde la perspectiva de cada actor.
- Priorizar funcionalidades **MVP vs Post-MVP**.
- Establecer una base sólida para fases posteriores (arquitectura, desarrollo, pruebas).

---

## Alcance

Las historias de usuario cubren los módulos mínimos del sistema:

- Cliente
- Administración / Vendedor *(en desarrollo)*
- Soporte y contenido *(en desarrollo)*

Cada módulo se documenta en archivos independientes para mantener orden, trazabilidad y escalabilidad.

---

## Convención de historias de usuario

Formato utilizado:

Como [actor],
quiero [acción],
para [beneficio].


Convención de identificación:
- **HU**: Historia de Usuario  
- **CL**: Cliente  
- **ADM**: Administrador / Vendedor  
- Numeración secuencial según el flujo funcional

Ejemplo:

## HU-CL-01 – Ver catálogo de productos


---

## Criterio de priorización

- **[MVP]**: Historias indispensables para que el sistema funcione.
- **[Post-MVP]**: Funcionalidades complementarias para futuras versiones.

---

## Acompañamiento y enfoque

Las historias de usuario fueron construidas con acompañamiento en el rol de **Product Owner y mentor**, asegurando:
- coherencia funcional
- alineación con un negocio real
- ausencia de decisiones técnicas prematuras
- enfoque en valor y experiencia del usuario
